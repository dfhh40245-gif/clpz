**Overall: 55/100 for the current prelaunch implementation.** The local clipping pipeline works, but security boundaries, recovery, editing, and account flows contain release-blocking defects. This is an engineering assessment, not a certification or a percentage of tests passed.

The score does **not** deduct points simply because GitHub, Vercel, Supabase, or payments have not been activated. It assesses the code already present, including whether its proposed deployment and database configuration would work safely. Missing external integrations are listed separately from confirmed bugs.

**Fix before exposing account or credit services.**

1. **Critical on a fresh account service: anyone who registers the configured admin email first becomes admin.** `require_admin()` compares the email string and never checks verification or a separately assigned role. The isolated probe signed up as the configured owner address, received `email_verified: false`, and accessed `/api/admin/users` with HTTP 200. This is a bootstrap vulnerability, not proof an existing owner's password can be bypassed. Provision the admin role through a trusted operation tied to an immutable user ID; require verified identity. [Authorization code](C:/Users/oSSS/Desktop/clpz-actual/backend/main.py:156).

2. **Critical before applying Supabase migration: the privileged credit RPC remains executable through `PUBLIC`.** `grant_credits` is `SECURITY DEFINER`, accepts an arbitrary user and amount, and only revokes execution from `anon, authenticated`. Under default function privileges, callers still inherit execution from `PUBLIC`, bypassing the intended service-only boundary. Revoke from `PUBLIC`, `anon`, and `authenticated`, explicitly grant only the intended service role, and test RPC denial as both client roles. Do creation and grants in a transaction. This is a static finding under default privileges; no live database was deployed. [Migration](C:/Users/oSSS/Desktop/clpz-actual/supabase/migrations/0001_initial_schema.sql:196). The privilege behavior is documented by [PostgreSQL](https://www.postgresql.org/docs/current/sql-createfunction.html#SQL-CREATEFUNCTION-SECURITY) and [Supabase](https://supabase.com/docs/guides/database/functions).

3. **High: hosted and local access modes are not separated on the backend.** Anonymous job creation is accepted even with debug off, consumes no credits, and anonymous jobs are visible to other callers. The desktop UI's `?desktop=1` flag is not a security boundary. This is acceptable as an intentional private local workflow, but exposing this same backend creates a free-processing and data-access path. Add an explicit server-side local/hosted mode. Require authenticated, authorized accounts for any hosted workspace; keep desktop processing local. [Job creation](C:/Users/oSSS/Desktop/clpz-actual/backend/main.py:596), [visibility](C:/Users/oSSS/Desktop/clpz-actual/backend/main.py:640).

4. **High for local-service protection: no Host/Origin enforcement or per-launch capability protects anonymous mutation endpoints.** A cancellation POST with an untrusted Origin returned 200; an arbitrary Host was accepted. CORS controls which responses browsers can read; it does not reject all cross-origin actions. Add trusted Host validation and Origin checks for browser mutations, plus a per-launch token for desktop API access. The actual launchers bind loopback, which reduces exposure. DNS rebinding/browser-to-local attackability depends on browser protections and was not demonstrated end to end. [Middleware and access model](C:/Users/oSSS/Desktop/clpz-actual/backend/main.py:69).

5. **High: the current-password reset endpoint bypasses login throttling.** `/api/auth/reset` calls password verification without a rate limiter. Fifteen consecutive incorrect guesses all returned 401; none returned 429. An attacker can use it as a second password-guessing endpoint. Apply per-account and per-client throttling to every password-verifying operation, not just login. [Reset endpoint](C:/Users/oSSS/Desktop/clpz-actual/backend/main.py:376).

6. **Medium: password and email delivery policies need strengthening.** Password minimum is six characters; PBKDF2-SHA256 uses 100,000 iterations. Migrate hashes with versioned parameters and rehash on successful login, or delegate account auth to the chosen provider. Current [OWASP guidance](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) recommends Argon2id or a stronger PBKDF2 work factor. Set reasonable input length limits. Separately, the email fallback prints reset/verification codes even when debug is off; endpoints claim mail was sent without checking delivery results. Restrict code logging to explicit development mode and fail account-service startup or delivery clearly when email configuration is missing. [Password hashing](C:/Users/oSSS/Desktop/clpz-actual/backend/auth.py:23), [email service](C:/Users/oSSS/Desktop/clpz-actual/backend/email_service.py:70).

**Confirmed functionality and recovery defects.**

7. **High: retry after analysis/render failure crashes.** When both `parse` and `analyze` are in completed stages, parsing is skipped, but the function later uses a local `transcript` variable that was never assigned. Reproduced `UnboundLocalError`. Reload the saved SRT/word data on resume, or persist and reload a validated transcript object. Test failure and retry at every stage. [Resume logic](C:/Users/oSSS/Desktop/clpz-actual/backend/jobs.py:761).

8. **High: muted export always fails validation.** The editor adds `-an`, intentionally removing audio. `_validate_output` then rejects the output because there is no audio stream. Normal export returned 200; muted export returned 500 with `No audio stream found`. Let validation accept intentionally muted outputs or preserve a silent track. [Mute handling](C:/Users/oSSS/Desktop/clpz-actual/backend/main.py:1252), [validator](C:/Users/oSSS/Desktop/clpz-actual/backend/jobs.py:186).

9. **Medium: 0.25× export produces an invalid audio filter.** The API accepts speed >=0.25, but builds `atempo=0.25`; bundled FFmpeg requires each atempo stage to be at least 0.5. Reproduced HTTP 500. Chain two 0.5 stages for quarter speed, and test the full supported speed range. [Speed filter](C:/Users/oSSS/Desktop/clpz-actual/backend/main.py:1217).

10. **Medium: long-video overlap merging duplicates speech.** Chunk results are concatenated; duplicate checking happens before timestamp sorting and compares only adjacent words. Repeating an identical two-word overlapping chunk produced four words and two duplicate segments. Align and reconcile the complete overlap interval; test real boundary jitter and repeated words. Chunk language is also discarded as `unknown`. [Chunk merge](C:/Users/oSSS/Desktop/clpz-actual/backend/pipeline/transcriber.py:229).

11. **Medium: editor preview does not reflect the edits being exported.** The vanilla editor updates an edit-state object, but the video continues playing the original rendered clip. Text overlays appear in a list rather than on the preview; speed/volume/trim controls do not synchronize the preview. Saved edits are copied to disk without becoming a persisted editable version in the project. Implement preview synchronization and versioned edit state, or clearly distinguish a parameter form from a live editor. Marketing also advertises caption/reframe editing beyond the controls currently implemented. [Editor](C:/Users/oSSS/Desktop/clpz-actual/frontend/clpz.html:538).

**Data integrity and future payments.**

12. **High before charging users: idempotency keys are global and not bound to user, operation, or request content.** An anonymous caller reusing an authenticated caller's key received the original job ID with 200. The ownership check still blocked reading it with 404, so this is not a demonstrated private-video disclosure. It nevertheless deduplicates unrelated callers and different operations incorrectly. Use a unique `(user-or-local-session, operation, key)` constraint and reject replays with different payload fingerprints. [Job deduplication](C:/Users/oSSS/Desktop/clpz-actual/backend/jobs.py:102).

13. **High before charging users: payment recording and credit fulfillment are separate commits.** Injecting a failure after `record_payment` but before the credit grant left a recorded sale with zero credits; replaying the sale became a duplicate no-op. Record and fulfill atomically, or persist a fulfillment state that retries can finish. Reversal status changes have a similar ordering risk. Store the original granted amount and account mapping rather than recomputing from current product configuration. Email matching also accepts unverified accounts despite its docstring. [Webhook fulfillment](C:/Users/oSSS/Desktop/clpz-actual/backend/gumroad.py:139).

14. **High before charging users: refund and signup-bonus idempotency is not atomic.** The check and mutation use separate database calls, allowing concurrent requests to pass the same check. Sequential duplicate refund already raises `NameError` because `get_credit_balance` is undefined in `credits.py`. Use a unique ledger operation key and one database transaction for each grant/refund. A replay should return the existing result. [Refund](C:/Users/oSSS/Desktop/clpz-actual/backend/credits.py:82), [signup bonus](C:/Users/oSSS/Desktop/clpz-actual/backend/credits.py:30).

15. **Medium: some failure paths lose charge/recovery consistency.** The low-disk-space branch returns before the general exception/refund handler. Retry does not establish a new charge after a previously refunded failure. Upload validation refunds sometimes omit the job reference, and retained deduplication mappings can return a cancelled upload for a resubmission. Specify whether retries are free, then implement a job/charge state machine covering upload rejection, disk-full, interruption, refunds and retry. [Low-disk branch](C:/Users/oSSS/Desktop/clpz-actual/backend/jobs.py:688), [upload](C:/Users/oSSS/Desktop/clpz-actual/backend/main.py:669).

16. **Medium: persistence errors can be silently ignored and the backup helper fails on its second run.** `_persist` swallows both JSON-write and database errors, so the UI may report progress that did not survive a restart. JSON and SQLite also form two independently written stores. Use one authoritative durable store, atomic file replacement for derived snapshots, and visible persistence failures. `backup_database()` always targets the same `.db.bak`; the second call reproduced `output file already exists`. Add versioned backup destinations and a tested restore operation, including media assets. [Persistence](C:/Users/oSSS/Desktop/clpz-actual/backend/jobs.py:172), [backup](C:/Users/oSSS/Desktop/clpz-actual/backend/database.py:1012).

17. **Medium before cloud credits: Supabase idempotency checks the wrong fields.** The function checks `external_ref + txn_type` when a key is present, instead of checking the actual key and user. Two distinct operations sharing a reference can be silently skipped, while concurrent same-key requests can hit the unique constraint rather than return the prior result. Use a correctly scoped unique key and transaction-safe replay handling. Also enforce the documented subscription lifecycle constraints, and test credit grants/revocations as actual database roles. [Credit SQL](C:/Users/oSSS/Desktop/clpz-actual/supabase/migrations/0001_initial_schema.sql:209).

**Performance and resource controls.**

18. **High for reliability: the job deadline is cooperative, not an absolute timeout.** It is checked at stage boundaries; Whisper callbacks only update progress. A stuck model call can retain the only semaphore slot indefinitely. Some ffprobe calls have no timeout and transcription subprocesses do not use the job process registry. Put heavy work in cancellable worker processes, propagate a deadline through all subprocess calls, and check cancellation between audio chunks. The passing cancellation test covers a registered child process, not all these code paths. [Pipeline deadline](C:/Users/oSSS/Desktop/clpz-actual/backend/jobs.py:680), [transcriber probe](C:/Users/oSSS/Desktop/clpz-actual/backend/pipeline/transcriber.py:117).

19. **High if the backend is shared: uploads and edits bypass important resource controls.** Multipart parsing occurs before the handler's 2 GB copied-byte cap, upload has no forge limiter, and synchronous ffprobe calls inside the async upload handler can block the event loop. Every job gets a thread that waits on a semaphore; queue admission is unbounded. Edit renders bypass that semaphore and concurrent edits target the same output file. Enforce request-body limits before multipart parsing, bound the queue, move probes off the event loop, and run edits through the worker pool with per-clip locks and temporary output files. [Upload](C:/Users/oSSS/Desktop/clpz-actual/backend/main.py:669), [edit](C:/Users/oSSS/Desktop/clpz-actual/backend/main.py:1272), [job slot](C:/Users/oSSS/Desktop/clpz-actual/backend/jobs.py:664).

20. **Medium: project-list requests become unnecessarily expensive as libraries grow.** Every request deep-copies every job; payloads include caption words and detailed render metadata. Legacy metadata backfilling can invoke FFmpeg while serving GET requests. Automatic cleanup is off, and there is no normal user-facing project delete action. Paginate lightweight project summaries, fetch detailed clips on demand, perform backfill in the background, and add explicit storage management. [List API](C:/Users/oSSS/Desktop/clpz-actual/backend/main.py:656), [backfill](C:/Users/oSSS/Desktop/clpz-actual/backend/jobs.py:1024).

21. **Medium: the login animation performs avoidable GPU work.** It resets canvas dimensions each animation frame; its effect depends on pointer state and creates shaders/programs/buffers without deleting them on cleanup. Initialize resources once, update uniforms through refs, resize only when needed, release WebGL resources, and honor reduced motion/hidden-page behavior. Profile this before adding more effects, particularly while the desktop pipeline is using memory. This is code-based; no FPS or leak-size claim was measured. [Animation](C:/Users/oSSS/Desktop/clpz-actual/frontend-app/src/components/ui/LoginForm.tsx:38).

**Deployment, user experience, and engineering quality.**

22. **High before Vercel: the site root is blank and the configuration does not represent a working account deployment.** Browser inspection reproduced the router warning that `/` does not match basename `/new`. The logo links to `/`, so it also exits the working route. `rootDirectory` is absent from the official `vercel.json` schema; choose the project root through Vercel project settings or build the subdirectory explicitly. The root package's build only generates legacy frontend config and requires Supabase env values. React still calls same-origin `/api/*`, and the static deployment defines no implementation or proxy for those calls. Fix the route/base-path and build root, then explicitly connect the chosen auth/backend service. Adding env values alone will not do that. [Router](C:/Users/oSSS/Desktop/clpz-actual/frontend-app/src/App.tsx:20), [API](C:/Users/oSSS/Desktop/clpz-actual/frontend-app/src/lib/api.ts:1), [Vercel config](C:/Users/oSSS/Desktop/clpz-actual/vercel.json:1), [official schema](https://openapi.vercel.sh/vercel.json).

23. **Medium: public account controls and accessibility are unfinished.** Google sign-in has no action; Forgot Password is `href="#"`. Form labels are neither associated with IDs nor wrapped around inputs; the browser accessibility tree reported unnamed text fields. Connect or remove inactive controls, associate labels and autocomplete attributes, expose errors as alerts, test keyboard focus, and check contrast over the moving background. The small signup-footer text was difficult to read in the inspected screenshot. A mobile-width landing check found no horizontal document overflow; this is not a complete device/accessibility audit. [Form](C:/Users/oSSS/Desktop/clpz-actual/frontend-app/src/components/ui/LoginForm.tsx:165).

24. **Medium: clean installs and CI are not reproducible enough.** `python-multipart` is required by FastAPI's File/Form routes but missing from backend requirements; test-only `requests` is also undeclared as a test dependency. Python dependencies use broad lower bounds. CI suppresses install errors and falls back to a different dependency set; frontend CI falls back from `npm ci` to `npm install`. Add complete runtime/test manifests, resolve and lock the supported Python environment, use deterministic installs, and let dependency failures fail CI. Add production-mode auth, resume, export and SQL permission regressions; the existing three UI tests do not cover the public React routes. [Requirements](C:/Users/oSSS/Desktop/clpz-actual/backend/requirements.txt:1), [CI](C:/Users/oSSS/Desktop/clpz-actual/.github/workflows/ci.yml:1).

25. **Medium: package and release instructions disagree with the implementation.** `build_windows.py` assembles a folder but does not invoke Inno Setup to produce the advertised installer, and copies whatever React `dist` already exists without rebuilding it. Debug is set with `setdefault`, so inherited `CLPZ_DEBUG=1` can survive despite claims the package forces it off. Several docs describe debug's old default and stale build/output paths. The Git index contains approximately 289 MB of native binaries. Establish one release command that builds frontend/backend/installer, verifies the artifact and first run, records version and hashes, inventories dependency notices, and tests update/uninstall data retention. Treat code signing and hosted release URLs as planned launch work. [Build script](C:/Users/oSSS/Desktop/clpz-actual/packaging/build_windows.py:125), [release notes](C:/Users/oSSS/Desktop/clpz-actual/docs/RELEASE.md:1).

The installed Click advisory concerns `click.edit()`; no direct use of that function was found in the reviewed app. Treat it as an environment/dependency update item rather than a proven remotely exploitable CLPZ endpoint. Fixing the current huggingface-hub constraint requires a newer compatible Click than merely the advisory's minimum patched version. Evidence comes from [official PyPI metadata](https://pypi.org/pypi/click/8.1.8/json), with the saved package-by-package results below.

**Planned integration work, not evidence of a current breach.** Supabase is presently a migration and setup guide; runtime accounts and credits are local SQLite. The website-to-desktop session/license handoff is not implemented, and the success page cannot actually know the desktop app is ready. There is no completed installer download journey. Payments contain scaffolding but lack a verified provider contract and end-to-end checkout/renewal/refund/reconciliation tests. The handler expects signed JSON with nested `event/sale`; validate that against the exact provider webhook format before connecting it. Do not distribute service-role, payment, or transactional-email secrets in a desktop binary. Local editable credits cannot serve as authoritative paid entitlements. Decide whether the commercial product is free local processing, paid features, subscriptions, or credit purchases, then implement a consistent cloud entitlement boundary.

**Recommended fix order.**

1. Fix admin authorization, Supabase RPC permissions, and server-side local/hosted isolation before enabling external account services.
2. Fix retry, mute, slow-speed export, overlap merging, and duplicate refunds; add regressions for the observed failures.
3. Make ledger operations atomic; enforce queue/body limits and reliable cancellation, deadlines, persistence, backup and restore.
4. Correct Vercel routing/build setup, account controls, accessibility and signup-to-download flow.
5. Integrate the chosen cloud auth/entitlements/payment contract and test the actual provider lifecycle in a sandbox.
6. Lock dependencies and produce a repeatable installer; run clean-machine, offline, upgrade, low-disk and low-RAM acceptance tests before public release.
